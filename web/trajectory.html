COMMENT MARCHE TEST 1 / TEST 2

Le mécanisme

Cliquer TEST 1 ou TEST 2 fait deux choses en même temps : ça étiquette la prochaine prise, et ça démarre un enregistrement rosbag lancé détaché du navigateur, côté PC. Ce détachement est le point important : le buffer de trajectoire du site est perdu à chaque redémarrage du backend (ça arrive : surchauffe, chien de garde, estimateur qui plante) — l'enregistrement détaché, lui, continue d'écrire sur disque même si le site se coupe.

MINS et openVINS sont TOUJOURS capturés ensemble, quel que soit le bouton actif à l'écran. Le choix Test 1/Test 2 ne change que le préfixe des fichiers à l'export, jamais ce qui est enregistré. Si un enregistrement est en cours et que tu cliques sur l'autre test, le site demande confirmation, termine et sauvegarde le premier, puis démarre le second.

Export vers MATLAB

Le bouton EXPORT TO MATLAB écrit web/exports/test1_mins.csv, test1_vins.csv et test1.mat (idem pour Test 2), et si MATLAB tourne sur le PC, ouvre automatiquement le tracé MINS-vs-openVINS de ce tour. Refaire un export sous la même étiquette écrase le précédent : refaire un essai raté remplace, ça n'accumule pas de variantes.

Le protocole "rectangle mesuré"

Pour comparer les deux estimateurs à une vraie mesure au ruban, pas seulement entre eux :

  1. Marquer un rectangle au sol (ruban), dimensions mesurées, pas à l'œil.
  2. TEST 1 → faire le tour du rectangle → EXPORT. (la trace MINS de ce tour sera celle qu'on retient)
  3. TEST 2 → un second tour, indépendant → EXPORT. (la trace openVINS de celui-là sera retenue)
  4. Depuis un terminal sur le PC — aucun bouton du site ne fait encore ça :
    • compare_tests('web/exports/test1', 'web/exports/test2') — accord entre les deux tours (déjà existant)
    • plot_rectangle_test('web/exports/test1', L, l, 'mins') — écart en % contre les dimensions mesurées (nouveau)
