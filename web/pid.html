PID Regulation

AUTO mode used to be pure bang-bang: full speed until a hard obstacle trip, a fixed-angle blind pivot, then full speed again — no proximity awareness in between. Three PID loops now regulate patrol steering, beacon centering, and — the one that actually stops the robot from ramming into walls — a continuous speed governor that slows down progressively as it approaches an obstacle, well before the emergency trip.

SAFETY

Obstacle speed governor

Error = measured corridor clearance (depth camera, p5 percentile of a 3-way-tiled ROI) minus a 1.5 m slowdown threshold. Positive error (clear ahead) does nothing; negative error (something approaching) scales ADVANCE_LIN down, continuously, as low as 30% of normal speed.

  • Kp = 0.0012 — no prior P gain existed here to reuse; tuned to reach the floor slightly before the 600 mm hard-trip distance, favoring margin on a first live trial
  • Ki = 0 — deliberately off: the robot can sit blocked with sustained error for a while (waiting on a dual-confirm grace window, an obstruction) — integrating that would wind up for no benefit; anti-jam ESCAPE logic already handles "stuck"
  • Kd = 0.15 — damps sudden clearance changes; uses the PID's own internal filtered derivative since corridor depth has no upstream EMA to reuse

Strictly additive: the binary 600 mm trip and the reactive bounce-pivot are untouched — this only makes the robot slow down earlier, never replaces the hard stop.

PATROL

Patrol steering

Error = EMA-smoothed bearing toward the widest open depth sector ("grand chemin"), setpoint 0 (drive straight at it). Replaces a bare proportional term with the same gain, plus damping.

  • Kp = 0.8 — reused as-is from the field-tuned OPEN_STEER_KP constant
  • Ki = 0 — the target corridor changes every tick, there is no fixed setpoint to integrate toward; would also fight the separately-tuned yaw-drift trim already applied at publish time
  • Kd = 0.1 — damps fast swings, e.g. passing a doorway, without fighting the existing anti-zigzag EMA upstream

Output clamp unchanged: ±0.25 rad/s, same as before the PID swap.

LOCK

Beacon centering

Two instances: align-in-place (rotate to center the beacon before advancing) and approach (keep it centered while driving toward it). Error = pixel offset from frame center (approach) or normalized fraction (align).

  • Kp — reused as-is: 0.25 (align) / 0.004 (approach), the exact prior proportional gains
  • Ki — small on align only (0.05, tightly clamped) — a fixed optical-axis bias is plausible given this rover's known asymmetric wheel slip; off for approach, where error should already be small after align has converged
  • Kd — 0.06 / 0.05 — conservative, both consume an already LED/checkerboard-EMA-smoothed center (_led_ema / _lm_ema), so no extra filtering needed

The centered/not-centered hysteresis band (±8% enter, ±14% exit) that stops chatter is untouched — the PID only smooths the steering command itself.
